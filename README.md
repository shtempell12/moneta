# Монета

[![CI](https://github.com/shtempell12/moneta/actions/workflows/ci.yml/badge.svg)](https://github.com/shtempell12/moneta/actions/workflows/ci.yml)

Веб-сервис для ведения семейного бюджета: траты автоматически раскладываются по личным категориям пользователя, есть план/факт по месяцам, цели накопления и выгрузка в Excel.

## Что уже работает

- Регистрация и вход: пароли в argon2, серверные сессии, защита от перебора паролей и CSRF
- Загрузка выписки банка (CSV/XLSX) с автоопределением колонок и защитой от дублей
- Автокатегории: сначала по истории пользователя, затем по категории банка
- Исправление категории в один клик; магазин запоминает категорию, которую выбирают чаще
- Ручной ввод трат (наличные), метка «кто потратил», свои категории
- План на месяц по категориям и план/факт на дашборде
- Цели накопления: сколько откладывать в месяц до срока
- Удаление аккаунта со всеми данными (152-ФЗ)

## Стек

Python 3.12, FastAPI, PostgreSQL 16, Docker Compose. Зависимости — через [uv](https://docs.astral.sh/uv/).

## Запуск

Нужны Docker Desktop и uv.

```bash
cp .env.example .env    # затем поменяй пароли в .env
make up                 # поднимает app + Postgres и применяет миграции
curl localhost:8000/health
```

Сайт: http://localhost:8000 (регистрация, вход). Документация API: http://localhost:8000/docs

## Демо

```bash
make up
make demo-data    # синтетическая выписка за 3 месяца → data/demo_statement.csv
open http://localhost:8000
```

Сценарий: зарегистрироваться → «Загрузить выписку» → выбрать `data/demo_statement.csv` →
проверить колонки → «Траты»: поправить категорию (например, «Студия развития Лучик» →
своя категория «Развивашки») → остальные операции магазина получат ту же категорию →
«Дашборд»: траты по категориям и доля автоматически разложенных операций →
«План» и «Цели».

Выписка синтетическая: реальные выписки в репозиторий не попадают (`data/` в `.gitignore`).

## Исследование

Офлайн-проверка гипотезы H-ML1: какой способ категоризации точнее на истории пользователя.
Последний месяц каждого пользователя — проверка, более ранние — обучение. Сравниваются:
категория банка (точка отсчёта), «последний выбор», «чаще выбирают», классификатор
TF-IDF + логистическая регрессия и каскад из них.

```bash
make research                        # на синтетических данных — проверка, что код работает
make research DATA=data/labeled.csv  # на реальных обезличенных данных
```

Гипотеза H-DEV2 — читаются ли выписки разных банков без ручной настройки колонок:
положите файлы в `data/statements/` с именами вида `sber_октябрь.csv` (банк до «_») и запустите
`make statements-check`.

Формат данных — в `research/dataset.py`. Таблицы результатов сохраняются в `data/reports/`.
Реальные данные и результаты по ним в репозиторий не попадают.


## Миграции

Структура базы описана в `app/db/models.py`, её версии — в `migrations/versions/`.

```bash
make migrate                                            # применить новые миграции
docker compose exec app alembic downgrade -1            # откатить последнюю
# создать миграцию после изменения моделей (с хоста база доступна как localhost, а не db)
DATABASE_URL=postgresql+psycopg://moneta:<пароль>@localhost:5432/moneta \
  uv run alembic revision --autogenerate -m "описание"
```

Для `make test` должен быть запущен контейнер с базой (`make up`): тесты создают отдельную базу `moneta_test`.

## Бэкап базы

```bash
make backup                                     # дамп в backups/
make restore FILE=backups/moneta_<дата>.sql     # восстановление
```

```
  api/           JSON-эндпоинты
  web/           страницы (Jinja2 + HTMX)
  core/          конфиг, безопасность
research/        офлайн-оценка категоризации
tests/           тесты
```
